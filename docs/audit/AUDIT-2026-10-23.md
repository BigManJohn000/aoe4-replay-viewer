## What the audit measured

- **Parity harness passes today:** `node viewer3d/tools/parity-check.mjs aoe4_245598603` → 790,405 comparisons over
  1,992 entities at 120 times, `parity OK`, exit 0. The model layer agrees. **Everything below is outside what that
  harness compares**, which is why the drift survived.
- **Roster:** 3,013 catalogue blueprints and 2,094 stat entries collapse to **391 distinct visual IDs** — 227 unit
  types, 164 structure types (`roster.json`).
- **Animation store:** 36 rigs, 490 clips, 939 blueprint mappings, 0 orphan clips, 0 dangling state references,
  0 weapon styles without an archetype. 58 clips are unreachable: 53 through state names the engine never asks for,
  5 as style/job variants the resolver never selects.
- **Assets:** 32 unit types fail the exact stats ↔ catalogue join for a 3D model, but 12 of them have one under the
  13 known aliases, so **20** genuinely lack a model; likewise **24** (not 26) lack an icon. 0 of the 163 genuine
  structures have skeletal animation (the roster's 164 includes `worker-elephant`, a unit with a dummy building
  blueprint).
- Roster coverage caveat: the stats-id ↔ catalogue-id join misses 13 units (token order, variant digits, one
  misspelling; 11 distinct catalogue targets), so the animation store covers ~154 of 227 unit types, not 141.

## 1. 2D ↔ 3D parity — the five root causes

1. **Two replay models for one recording.** 3D builds the 2D model (`M2 = RV.prepare`, `viewer3d/viewer.js:973`)
   *and* its own (`R = new Replay`, `:1017`). The renderer reads `R`; marks and panels read both (the Players panel
   queried `R` until A2; it now queries `M2`).
2. **Panel logic was ported, not shared.** `viewer3d/core/analysis.js` re-implemented `statsAt` and `armyAt` (from
   `viewer/model.js`, `armyAt` with a different computation) and `techTable`, `killFeed`, `jumpFight` (from
   `viewer/app.js`, adapted to return data instead of DOM; `jumpFight` with different next-fight rules). *Fixed by A2:
   both viewers now query `viewer/model.js` and `analysis.js` is deleted.*
3. **Two UI shells** with separate HTML/CSS/handlers (2D: 5-tab sidebar; 3D: 3-tab drawer) — labels, grouping,
   defaults and shortcuts drift.
4. **No shared ID registry** joining `stats.js` ↔ `catalog.json` ↔ `anims/index.json` (this already causes 13
   stats-id/catalogue alias misses in the animation join).
5. **The parity gate checks the model and some panel-query facts** (eco and fight analysis; the tech table, stats,
   army and kill-feed comparisons went away with A2, as both viewers now run the same queries), but never the rendered
   panel numbers, UI defaults or asset coverage.

Most consequential verified drifts: the Players "Army" column was entity-derived in 2D but a 5 s series in 3D (fixed by
A2); `other`-category entities count as units in 3D but not 2D (a classification difference that does not reach army
or on-screen totals); farm fog sight differs (0 in 2D vs 15 in 3D; docks and walls agree because 3D reads the
catalogue sight first); fight jump lead 5 s vs 3 s (fixed by A2: 5 s in both); 2D has no victory
conditions; 3D has no caster HUD, eco debt, "vs 2000+" unit benchmarks or range rings. Full tables:
`parity-2d-3d.md` §3.

## 2. Animations — the three checklists in one line each

1. **Complete for their role:** 17 of 30 standalone archetypes, among them `base_archer`, `base_swordsman`,
   `base_spearman`, `base_horse_combined`, `base_camel_combined`; every weapon style resolves. "Complete" is about
   states, not reachability: these rigs still hold dead clips (archer 3, swordsman 2, spearman 2, horse 5, camel 2).
   `base_civilian` plus its **6** job rigs (butcher, farmer, fisherman, forager, logger, miner) cover villager work;
   `base_civilian` lacks `carry_idle` and holds 3 dead clips. 7 of 12 animal rigs miss required states (bigcat,
   crocodile, fox, wolf: `dead`; reindeer: `jog`; land/water monsters: `sprint`, `death`, `dead`).
2. **Present but not wired:** 58 clips — `stop` 41 (40 plain in 26 archetypes + 1 `stop@arquebus`), `dropoff` 8,
   `heal` 2, `mount`/`dismount` 2 (one archetype), `tool_*@herd` 3, `attack@swing` on `base_heavy_spearman` 2. 2D has
   no skeletal animation-state concept (its effects do animate), so "wired into 2D" can only mean icon tier + effects.
   *B1 wired `stop`, `dropoff` and `heal` (50 clips); the other 8 have no recorded trigger. The drop-off clip shows at
   only ~2 % of recorded drop-offs, as villagers rarely stand still at one (`animation-audit.md` Checklist 2).*
3. **Missing:** 20 unit types have no model; all 32 ship families and 26 of 29 siege families have no rig; 0 of 163
   genuine structures have skeletal animation (construction, ruin, packing and gates are procedural); 9 blueprints
   (attachments and gaia cases) are unmapped in the index. Monks are **not** missing death/flinch/attack at runtime:
   `base_monk` lacks them, but all 25 monk mappings layer `base_civilian` (`extra`), which supplies them. *Corrected:*
   `base_elephant_archer` is not a sliding unit but the tower crew rig (its blueprints ride a tower elephant), and every
   recorded `base_elephant_combined` user is melee; the real defect was the crew standing hidden inside its mount at
   ground level, fixed under B3.

## 4. Icons — ready to generate

- **391 IDs × 4 tiers = 1,564 ready-to-use prompts** in `ICON_PROMPTS.md` (machine-readable: `icon-prompts.json`).
- The shared style block is inside every prompt. The negative prompt is declared once (top of `ICON_PROMPTS.md`,
  `negative` in `icon-prompts.json`) and must be passed as the generator's separate negative field.
- Gold is a T3-T4 tier ornament, except where it is part of a unit's identity kit (66 families, identical across
  tiers). The two prompts that added tier gilding below T3 (`prelate` T2, `golden-tent` T1) are revised.
- One recolourable player-colour accent per icon is the rule; the 105 families that baked a fixed hue into the accent
  (e.g. "indigo sash") now name it `player-colour <region>`. Identical silhouette across tiers is a workflow
  rule (`ICON_STYLE_GUIDE.md` §6), not text inside the prompts.
- Naming `icon_<unit|structure>_<id>_t<tier>.png`; 512×512 PNG, transparent; legibility gate 22 px (the 2D key
  draws at `ICON_PX = 22`; the selection tray displays at 32×32).
- Integration points mapped in `ICON_STYLE_GUIDE.md` §7: 2D map figures (`RV.unitIcon`, 19 types today), legend,
  selection tray, unit card (currently an online AoE4World portrait), and the 3D tray (real game icons where the
  catalogue has one, procedural 2D art otherwise).
- **Interim option:** the 2D card already fetches per-age official portraits online; caching those locally would give
  tiered images wherever AoE4World publishes them. Availability for all 391 × 4 was not checked, and the card already
  falls back across ages and to procedural art.
