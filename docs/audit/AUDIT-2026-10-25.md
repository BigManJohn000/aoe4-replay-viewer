Date: 2026-10-25 · Repo: this repository · Read-only: no source file was changed by this audit.

Status 2026-10-26: after this audit the batch mode (`record_replay.py <folder>`, `Record replays.bat`) and the
input-log validator (`input_logger.py`, `validate_mechanics.py`) were removed, so F1's batch impact and the validator
mentions below no longer apply; F1's conversion crash itself is still open. F9 is fixed: `recorder_app.json` is
untracked and ignored. The other findings are open.

Scope: the recording pipeline (`recorder/recorder.lua`, `tools/`), both viewers (`viewer/`, `viewer3d/` incl. its
build tools), the two local HTTP services, and tracked-file hygiene. 2D/3D parity, UI/UX, animation coverage and icons
are covered by [`AUDIT-2026-10-23.md`](AUDIT-2026-10-23.md) and are not repeated here.

### F1 [P0] Recorder lines have no byte cap; one truncated line crashes conversion and aborts the batch

- Evidence: `recorder/recorder.lua:54,65-71`: `RR_Flush` batches `RR_MAXREC = 60` records per `print`, by count
  only. In `recordings/aoe4_247917342.rlog` line 26198 (`GN|1341.125|…`, 58 gaia records, 4,079 bytes) ends
  mid-record: `1000011076,projectile_bolt,-80`. The game's log line cap is about 4 KB ([INFERENCE] from the cut point;
  the exact engine limit was not measured). `tools/rlog.py:384` (`_gaia_new`) indexes `f[3]`/`f[4]` and raises
  `IndexError: list index out of range` (traceback reproduced through `convert.py:720 → :255 → rlog.py:439 → :433`).
  The record is a projectile that `convert.py:314` would have dropped through `GAIA_IGNORE`, but decoding fails first.
- Batch impact: `tools/record_replay.py:602-604` converts already-recorded replays in the pre-scan without a
  `try`, so this one file stops `record_replay.py replays` before any new replay is recorded. `is_complete()` accepts the
  damaged log (version, heartbeats and ERR count are fine), so every rerun hits the same file.
- Scale: 1 of 214 recordings today. Long `GN` lines happen when many neutral objects appear at once (a defeated
  player's buildings plus projectiles in this case), so later matches can hit it again.
- Fix: (1) `RR_Flush`: also flush when the joined line would exceed ~3,500 bytes. (2) Filter `GAIA_IGNORE`
  blueprints (projectiles, leftovers) in `RR_GaiaKind` so they are never logged (F13). (3) `rlog` decoders: raise a
  `ValueError` naming the line and record type on short records, and have the completeness check fail on structural
  corruption so the batch re-records instead of looping. (4) Wrap the pre-scan conversion per replay and report the
  failure like other skipped files. Existing damaged captures need re-recording.
- Effort: M.

### F2 [P1] One malformed request kills the 3D server

- Evidence: `viewer3d/serve.mjs:133` runs `new URL(req.url, "http://localhost")` outside any `try`. Reproduced on a
  throwaway instance (`node viewer3d/serve.mjs 18099`): `GET /` → 200; raw `GET //[` → connection reset, process
  exits with `TypeError: Invalid URL`.
- Impact: the viewer and its `/api/` proxy go down until restarted. A web page could plausibly trigger it with
  `<img src="http://127.0.0.1:8080//[">` (Host passes the allowlist). [INFERENCE]: browser loopback/private-network
  rules were not tested.
- Fix: wrap URL construction, answer 400; parse `req.url` as an origin-form path. Effort: S.

### F3 [P1] `build-assets.mjs` records failed model builds as covered

- Evidence: `viewer3d/tools/build-assets.mjs:2066-2069` adds a variant's model key to `entry.ages` as soon as it has
  parts, before export/build. Export failures (`:2093`) and build failures (`:2104`) are only logged; `:2107` copies only
  built models into `catalog.models`, while the blueprint keeps the dangling key. The "no model for" report (`:2118`)
  checks only for empty `ages`, and `--check` (`:1975-1979`) only for blueprint presence, which
  `tools/recorder_app.py:202-215` reads as "3D models up to date".
- Impact: one transient Essence/texture failure leaves units without models, and no automatic retry ever happens
  (the viewer filters unresolved keys at `viewer3d/viewer.js:235-239`).
- Fix: publish age keys only for built (or previously valid) models; make `--check` report unresolved keys; exit
  non-zero when any conversion failed. Effort: M.

### F4 [P1] Truncated `.rec` files pass validation

- Evidence: `tools/recfile.py:211-225` takes `end = o + size` and `b[p:p + bsz]` without checking either against
  the buffer; a short slice is accepted and `o = end` past EOF ends the loop normally. Agent probe: a tick declaring
  100 bytes with a 50-byte block and 1 real byte parsed as a valid tick. `tools/fetch_replays.py:109-113` relies on
  `recfile.load` to accept a download.
- Impact: a cut-off download gets a duration from partial data and is queued for recording instead of quarantined.
- Fix: bounds-check tick and block sizes (and chat records), raise `ValueError` so the existing quarantine runs.
  Effort: S.

### F5 [P1] Stop kills the recorder's controller: can orphan the game and skips graphics restore

- Evidence (traced): `tools/recorder_app.py:376-382` stops with `self.proc.kill()` on the Python recorder child.
  `tools/record_replay.py:486-499` lowers graphics and launches through Steam before it reports the game's identity;
  the parent's stop path (`recorder_app.py:530-533`) closes the game only when that identity is known, and the child's
  `finally` (`record_replay.py:568-575`) that restores graphics never runs after a kill.
- Impact: Stop during launch can leave a game running that blocks the queue; any Stop leaves the recording graphics
  preset installed for your next manual game until another recorder run restores it.
- Fix: cooperative cancel (signal or stop file) so the child closes its own game and restores graphics, with a bounded
  hard-kill fallback. Effort: M.

### F6 [P1] A summary that arrives later never reaches the published payload

- Evidence (traced): `tools/recorder_app.py:421-435` (download loop) fetches a missing summary for an already
  recorded match, clears `summary_error` and keeps it done; nothing calls `convert.convert`. The summary is only
  embedded at conversion (`tools/convert.py:777-779`), and `viewer/app.js:735-744` reads only the embedded copy.
- Impact: the dashboard drops its warning, but the viewer keeps lacking result, APM, scores and totals.
- Fix: reconvert from the existing `.rlog` (no game launch) when a summary arrives for a done item. Effort: M.

### F7 [P1] Duplicate display names join both players to one account in trends

- Evidence: `tools/trends.py:132` builds `by_name` with one entry per case-folded name (the last one wins); `:133` gives
  that entry to every player with the name. Agent probe: two players named alike with profiles 11 and 22 → `{1: 22, 2: 22}`.
- Impact: in a mirror-name match both rows get one account's result, rating and civ, and trend aggregates mix in the
  opponent's numbers. Rare in practice, silent when it happens.
- Fix: join on summary `profileId` when present; otherwise accept only names unique on both sides and consume each
  aoe4world entry once. Effort: S.

### F8 [P1] Game path interpolated into a PowerShell command

- Evidence: `tools/record_replay.py:365-370` runs `powershell -Command "(Get-Item '<game_dir>\<exe>')…"` with
  `check=True`; the path comes from Steam or the dashboard's folder picker (`recorder_app.py:285-291`) or `--game-dir`.
- Impact: an install folder with an apostrophe (`D:\Tom's Games\…`) makes build detection raise. Injection needs a
  folder the user picked, so no remote route.
- Fix: pass the path in an environment variable and use `Get-Item -LiteralPath $env:RR_EXE`, as `pick_folder`
  already does with its title. Effort: S.

### F9 [P1] `recorder_app.json` is tracked and un-ignored, yet holds local state

- Evidence: `.gitignore:21` has `!/recorder_app.json`. The committed copy is clean (0 matches for user paths), but the
  working copy's download error string contains the local user's home folder path: `recorder_app.py:418,424` store raw
  exception text and `:298-302` persist it.
- Impact: one `git add -A` or `commit -a` publishes the local username and folder layout, undoing the identity strip.
- Fix: untrack and ignore it; let `App` start empty or seed the showcase item from a separate sanitized fixture;
  store error messages with paths made relative to the repo. Effort: S.

### F10 [P2] Low quality: distant units keep their old pose after a paused seek

- Evidence: `viewer3d/viewer.js:3548-3553` (`animHeld`) returns the cached pose for distant or off-screen units on
  2 of 3 frames; `seek()` (`:4244-4251`) does not clear `v.us`, and the paused loop stops rendering once nothing is dirty.
- Impact: after seeking while paused, some far units show the previous clip (and, after a conversion, the previous
  team colour) until the camera moves. Fix: bump a seek generation that `animHeld` checks. Effort: S.

### F11 [P2] Havok tagfile reader loops forever on a zero-length section

- Evidence: `viewer3d/tools/havok/tagfile.mjs:10-14`: `p += len` with `len = 0` never advances and keeps pushing
  sections; `readTagfile` (`:44`) runs it before checking the `TAG0` tag. Only corrupt game files trigger it.
- Fix: require `len >= 8` and the section end inside the parent and buffer; throw with the offset. Effort: S.

### F12 [P2] `extract-clips.mjs --verify <typo>` passes with zero clips checked

- Evidence: `viewer3d/tools/havok/extract-clips.mjs:36-55` skips archetypes not matching the name and fails only on
  errors or mismatched counters, so an unknown name reports `clips 0 … 0/0` and succeeds; list/extract reject it
  (`:64-65`, `:73-74`). Fix: reject unknown archetypes and empty selections. Effort: S.

### F13 [P2] Recorder logs projectiles and neutral leftovers as gaia

- Evidence: `recorder/recorder.lua:366-369`: `RR_GaiaKind` returns 1 for any blueprint not matching
  dummy/spawn_marker/splat. `GN` lines mention `projectile_` in all 214 recordings; `convert.py:314` drops them
  (`rlog.GAIA_IGNORE`), so the payload is unaffected (0 projectile rows in the showcase payload).
- Impact: wasted log bytes, and these entries were part of the line that overflowed in F1. Fix: apply the
  `GAIA_IGNORE` patterns in `RR_GaiaKind`. Effort: S.

### F14 [P2] Recorder dashboard reads request bodies without a size cap

- Evidence: `tools/recorder_app.py:881` reads `Content-Length` bytes unconditionally. Bodies are read only after the
  `application/json` check, which a web page cannot pass without a CORS preflight the server never answers, so only
  local processes can send one. Fix: cap at e.g. 1 MB, answer 413. Effort: S.

### F15 [P2] No CI

- Evidence: no `.github/` (or other CI) in the tracked files. The 59 + 64 tests and the parity gate run only by hand.
- Fix: a Windows CI job for both suites and `parity-check.mjs` (the showcase payload is tracked). Effort: S.

### F16 [P2] History bloat

- Evidence: `git rev-list --objects main`: 377 blobs, 122.4 MB uncompressed, 51.1 MB of it no longer in HEAD
  (superseded `recordings/aoe4_245598603.rlog` 12.4 MB, two old `viewer/data/aoe4_245598603.js` 11.7 MB each, the old
  `viewer3d.png` 4.5 MB). Pack size 45.9 MB. `python/` adds 22 MB of tracked embedded CPython.
- Fix: commit the showcase data only when its format changes, or move it (and optionally `python/`) to a release
  asset or Git LFS. Effort: S-M.

## Checked, no issue found

- Local services: both bind 127.0.0.1 with exact Host allowlists (DNS rebinding blocked); recorder POSTs require
  `application/json` (forces a CORS preflight, so no form CSRF); the `/api/` proxy checks Origin and has a fixed
  upstream (no SSRF).
- Static serving: recorder mounts resolve and check containment (traversal, drive/UNC, symlinks); `serve.mjs` checks
  lexical containment. Downloads use fixed HTTPS endpoints with numeric IDs; replay ZIP members are read in memory,
  not extracted by name. Folder picker passes values through environment variables; other launchers use argv arrays.
- Time bases: 8 ticks/s agrees across `recfile`, `rlog`, camera tracks, mechanics and the validator; owner timelines,
  army lifetimes and cost lookups traced without a defect.
- `recorder_app.App`: state saves under the RLock with atomic replace; watch identity checks and wait loops bounded.
- Viewers: failed payload load shows a notice; missing summaries, empty fight lists and non-1v1 odds are guarded;
  2D plan atlas bounded and invalidated on zoom/DPR; `marks.js`/`fx3d.js` buffers bounded; `rv_bench.js` is used
  (`card.js:275-279`), not dead.
- Tests: regression tests assert behaviour (not wiring); parity harness compares model outputs per entity.
